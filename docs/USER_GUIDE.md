# Photo Desk 사용 가이드

Photo Desk는 **작업대에서 검토하고, 내사진에 정리하고, 필요한 사진을 공용에 발행하는**
개인용 macOS 사진 작업 도구입니다. Photo Backup은 수집, 우리집 사진관은 감상·논리적
큐레이션을 맡고, 원본의 물리 정리와 촬영일 교정은 Photo Desk에서만 합니다.

## 1. 시작하기

### 설치와 데이터

[Releases](https://github.com/HyunjoonKwak/photo_desk/releases)의 DMG에서 앱을
응용 프로그램에 넣습니다. 현재 개인용 빌드는 ad-hoc 서명이라, 신뢰한 공식 산출물이
macOS 격리로 차단된 경우에만 다음을 한 번 실행합니다.

```bash
xattr -dr com.apple.quarantine "/Applications/Photo Desk.app"
```

앱 데이터는 `~/Library/Application Support/com.acut.media/`에 있습니다. 데이터베이스를
수동 편집하거나 추가 테이블을 삭제하지 말고, 설정의 **데이터베이스**에서 백업·복원을
사용하세요.

### 라이브러리 등록

1. 왼쪽 앨범 패널 아래 **라이브러리 추가…**를 누릅니다.
2. 폴더를 고르고 역할을 지정합니다.

| 영역 | 용도 |
|---|---|
| 작업대 | 새 사진을 검토하고 정리하는 임시 구역 |
| 내사진 | 정리가 끝난 개인 사진, NAS 개인 폴더와 동기화 |
| 공용 | 가족과 나눌 사진, NAS 공용 폴더와 동기화 |
| 기타 | 흐름 밖의 아카이브·참조 폴더 |

내사진·공용은 Synology Drive Client가 양방향 동기화할 수 있습니다. 이 영역에서 파일을
이동·이름변경·휴지통 처리하면 NAS에도 전파될 수 있습니다.

## 2. 찾고 보기

왼쪽 아이콘 레일은 **모든 사진, 앨범, 스마트 앨범, 검색, 태그, 사람, 달력, 위치,
카메라** 순입니다. 아래에는 휴지통과 설정이 있습니다.

- 격자는 촬영일 기준으로 탐색하며 방향키로 이동합니다.
- `Shift`+방향키는 범위 선택, `Space`는 크게 보기입니다.
- `P` 남김, `X` 제외, `F` 즐겨찾기, `0`–`5` 별점을 사용합니다.
- `I`는 정보 패널, `C`는 두 장 이상 선택했을 때 나란히 보기입니다.
- 위치 화면은 GPS 사진을 지도에 표시하고, 온라인 지명 조회가 불가능하면 오프라인 국가
  정보와 좌표를 사용합니다.
- `?`를 누르면 전체 단축키 표가 열립니다.

사진의 태그·별점·판정 같은 논리 메타데이터는 Photo Desk DB에 저장됩니다. 파일명,
폴더, 촬영일 파일 기록을 바꾸는 물리 작업과는 구분됩니다.

## 3. 촬영일 감사·교정

사진을 선택한 뒤 아래 선택 패널의 **촬영일 감사**, 또는 폴더 메뉴의
**촬영일 감사·교정…**을 엽니다.

1. 감사 단계는 읽기 전용 dry-run이며 현재 값, 제안 값, 근거, 실제 기록 범위를 표시합니다.
2. 확실한 자동 후보만 고르거나 지역 날짜·시각을 수동으로 입력합니다.
3. 실행 결과에서 성공·실패 수를 확인합니다. 일부만 실패하면 실패 항목이 다시 선택됩니다.

| 포맷 | 기록 범위 | undo |
|---|---|---|
| JPEG/JPG | EXIF DateTimeOriginal, DateTimeDigitized, TIFF DateTime + mtime | 원본 바이트와 DB 값 복원 |
| HEIC/HEIF, RAW, PNG, TIFF, WebP, 동영상 등 | mtime + Photo Desk override; 파일 내부 메타데이터는 변경하지 않음 | mtime과 DB override 복원 |

JPEG는 수정 전에 원본 바이트를 백업합니다. EXIF가 없거나 날짜 필드가 일부만 있어도
압축 화소를 재인코딩하지 않고 표준 세 필드를 완성합니다. 손상된 구조나 APP1 크기 한계를
안전하게 처리할 수 없으면 그 파일만 실패로 남깁니다.

undo 원본은 라이브러리의 `.acut/capture-date-backups/<batch>/`에 유지됩니다. 성공적으로
undo하면 제거되지만, undo하지 않은 교정의 원본은 복구 가능성을 위해 자동 만료시키지
않습니다. 오래된 백업을 Finder에서 직접 지우면 해당 교정을 되돌릴 수 없습니다.

Kakao 계열의 13자리 epoch와 뒤의 순번은 날짜 근거로 해석하되, 시간대·자정 경계를
반영합니다. 자동 후보가 불확실하면 수동 교정을 사용하세요.

## 4. 사진 이동·복사와 공용 발행

사진을 선택해 **이동·복사**를 누르면 기존 또는 새 목적지 폴더를 고를 수 있습니다.

- **이동**은 원본 위치를 바꾸고 DB 경로를 함께 갱신합니다.
- **복사**는 원본을 유지하고 새 파일을 라이브러리에 등록합니다.
- 내사진→공용은 복사가 기본입니다. SHA-256 발행 원장으로 동일 사진 재실행을 건너뜁니다.
- 연결된 XMP 등 sidecar는 본 파일과 함께 처리합니다.
- 실행 전 같은 이름, 이름 변경 계획, 다른 볼륨 여부, Drive 동기화 경고를 확인합니다.
- 전부 건너뜀이나 부분 실패도 성공으로 닫히지 않고 결과를 보여 줍니다.

복사 undo는 목적지 사본과 sidecar가 실행 직후 SHA-256과 같을 때만 지웁니다. 사용자가
그 사본을 수정했다면 삭제를 거부하므로 먼저 변경 내용을 보존한 뒤 처리해야 합니다.

## 5. 이벤트로 정리하기

선택 사진의 **정리**를 열어 날짜와 이벤트 이름을 정하고 대상 영역을 고릅니다.
작업대→내사진은 이동, 내사진→공용은 원본을 남기는 발행 흐름이 기본입니다.

작업대 라이브러리 폴더 메뉴의 **이벤트 자동 발견…**은 촬영 시각 간격으로 후보를
묶습니다. 후보를 펼쳐 사진을 확인하고 필요한 묶음만 정리 화면으로 넘기세요. 현재 격자
페이지 밖의 사진도 선택한 후보 ID 전체가 고정되어 전달됩니다.

부분 실패 뒤 재시도할 때는 화면에 남은 실패 항목과 날짜·이벤트 이름을 다시 확인하세요.

## 6. 폴더 작업과 이름 감사

앨범 트리의 라이브러리·폴더 메뉴에서 다음을 실행할 수 있습니다.

- 새 폴더 만들기
- 이름 변경
- 같은/다른 라이브러리로 이동 또는 복사
- macOS 휴지통으로 보내기
- 날짜 폴더 이름 감사·교정

각 작업은 실행 전 대상 경로, 파일·폴더 수, 용량, 충돌, 볼륨 경계를 보여 줍니다. 다음은
실행 전에 차단됩니다.

- 라이브러리 루트 이동·이름변경·휴지통
- 폴더를 자신의 자식으로 이동·복사
- 오프라인 볼륨 또는 라이브러리 루트 밖 심볼릭 링크
- 빈 이름, 경로 구분자, 숨김 이름, 앱 내부 예약 이름

다른 볼륨 이동은 임시 목적지에 복사하고 SHA-256 manifest를 검증한 뒤 원본을 전환합니다.
같은 볼륨의 이름변경·이동·휴지통은 파일 내용을 읽지 않고 이름·크기·수정 시각만 journal에
남기므로 큰 폴더도 바로 끝나며, undo 때 그 값이 다르면 되돌리지 않습니다.
중간 실패 시 임시 사본을 정리하고 원본을 유지합니다. 폴더 이름 감사는 먼저 dry-run으로
후보와 충돌을 표시하고, 선택한 변경만 배치로 실행합니다.

## 7. 휴지통과 되돌리기

- 제외 표시는 아직 파일 이동이 아닙니다. 상태바의 **확정**을 눌러야 앱 휴지통으로 갑니다.
- 휴지통 화면에서 원래 위치로 복원하거나 영구히 비울 수 있습니다.
- 영구히 비운 파일은 앱에서 되돌릴 수 없습니다.
- 상태바의 **되돌리기** 또는 `⌘Z`는 가장 최근의 지원 작업을 배치 단위로 되돌립니다.
- 이후 파일이 바뀌었거나 목적지에 충돌이 생기면 안전을 위해 해당 항목 undo가 실패할 수
  있으며, 나머지 성공·실패 결과는 journal에 남습니다. 이동·이름변경·휴지통은 옮긴 직후의
  크기·수정 시각을 journal에 남겨 두고, 되돌릴 때 그 값과 다른 파일은 옮기지 않습니다.

## 8. NAS와 백업

Photo Desk의 NAS 기능은 Synology DSM 브라우저 업로드가 아닙니다.

1. 설정의 **NAS**에서 1차 구역과 내사진·공용 대응 경로를 확인합니다.
2. 새 사진은 rsync로 작업대에 받습니다.
3. 내려받은 사본을 검증하고 Photo Desk에서 정리합니다.
4. 내사진·공용 반영은 Synology Drive Client가 담당합니다.
5. NAS 1차 구역 정리는 내려받은 원장, 작업대에서 사라진 사실, 정리 또는 휴지통 기록을
   모두 확인한 항목만 NAS의 `#trash`로 옮깁니다.

설정의 **백업**은 별도의 대상에 사본을 만드는 기능입니다. 백업은 수집·복구 수단이지
정리 정본이 아닙니다.

## 9. 설정

설정은 10개 구역입니다.

| 구역 | 주요 내용 |
|---|---|
| 일반 | 표시, 촬영일·정렬 기본값 |
| 라이브러리 | 등록 폴더와 영역 |
| 탐색 | 격자·필터 동작 |
| 뷰어 | 크게 보기 동작 |
| AI | 모델과 분석 상태 |
| 데이터베이스 | 정보, 백업, 복원 |
| 백업 | 복사 대상과 실행 |
| NAS | rsync 연결, 검증, 1차 구역 정리 |
| 고급 | 캐시와 고급 동작 |
| 정보 | 앱 버전과 업데이트 |

현재 앱에는 Cron 스케줄러나 MCP 제어 서버가 없습니다.

## 10. 문제 해결

**다시 스캔하면 전체 SHA-256을 모두 다시 계산하나요?**

아닙니다. 일반 스캔은 경로·크기·mtime과 필요한 메타데이터를 갱신하고, 전체 해시는
중복 확정·발행·검증처럼 필요한 작업에서 계산하거나 저장된 값을 재사용합니다.

**Gallery와 사진 수나 순서가 다릅니다.**

먼저 Synology Drive 동기화 완료와 두 앱의 대상 폴더가 같은지 확인하세요. 물리 파일이
같아도 DB 스캔 시점, 필터, 촬영일 해석이 다르면 일시적으로 결과가 다를 수 있습니다.
물리 정정은 Photo Desk에서 하고 Gallery는 다시 색인합니다.

**원본 파일이 언제 바뀌나요?**

촬영일 교정, 이름변경, 이동, 휴지통, 폴더 작업을 실행했을 때만 바뀝니다. 검색·감사
dry-run·지도·AI 분석·태그·별점은 원본 파일을 바꾸지 않습니다.

**실패한 작업은 어떻게 확인하나요?**

대화상자의 성공·실패 수와 첫 오류를 확인하고, 실패 항목만 다시 시도합니다. 원본이나
목적지 파일을 Finder에서 임의로 덮어쓰기 전에 앱의 최근 작업과 undo 상태를 먼저
확인하세요.
